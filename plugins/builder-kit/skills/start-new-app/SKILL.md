# Start New App

1. Resolve communication and project delivery profiles from [profiles](../../references/workflow/profiles.md).
2. Interview only for material unknowns: purpose, users and workflows, success criteria, data and growth, platform/language, integrations, trust boundaries, local development, deployment, ownership, and prototype limits if applicable.
3. Apply the product/experience and relevant engineering lenses from [lens routing](../../references/lenses/lens-routing.md). Convert findings into decisions, not personas.
4. Read and follow [the develop-from-spec instructions](../develop-from-spec/SKILL.md). Do not scaffold before approval.
5. Route specialized platform, infrastructure, and deployment work through [external capability routing](../../references/workflow/external-capabilities.md); do not reproduce another skill's maintained instructions.
6. Establish a documented, production-like local run path from day one.
7. With explicit onboarding permission, merge thin instructions from [AGENTS.md.tmpl](../../templates/AGENTS.md.tmpl) and [CLAUDE.md.tmpl](../../templates/CLAUDE.md.tmpl). Preserve existing files and local rules; never overwrite them.
8. Scaffold only the approved minimum, verify the real entry path, and report evidence and deferred hardening.

Prototype projects must also read [prototype delivery](../../references/workflow/prototype-delivery.md). Never present a prototype as production-ready.
