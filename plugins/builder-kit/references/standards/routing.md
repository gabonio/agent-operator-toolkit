# Standards Routing

Use repository instructions, manifests, file types, and the changed boundary to select standards. Load only matching files, not this entire directory. These are correctness guides, not a ranking of languages or permission to replace an established stack.

| Task or boundary | Read |
| --- | --- |
| TypeScript or JavaScript, browser or server | [TypeScript/JavaScript](typescript-javascript.md) |
| Browser UI, components, styling, accessibility | [frontend](frontend.md), plus the language guide when relevant |
| Python | [Python](python.md) |
| Java | [Java](java.md) |
| C++ | [C++](cpp.md) |
| Go | [Go](go.md) |
| C# or .NET | [C#/.NET](csharp-dotnet.md) |
| SQL, including queries generated by an ORM | [SQL](sql.md) |
| Rust | [Rust](rust.md) |
| Kotlin | [Kotlin](kotlin.md) |
| Swift | [Swift](swift.md) |
| PHP | [PHP](php.md) |
| Ruby | [Ruby](ruby.md) |
| Jenkins pipelines | [Jenkins](jenkins.md) |

Combine only intersecting guides: Kotlin/JVM can need Java interop rules, not Java syntax preferences; a .NET service with SQL changes needs both guides. Language choice alone does not trigger UI, database, or CI guidance. For an undecided stack, use [specification discovery](../workflow/specification.md#conditional-stack-selection-interview) before choosing standards.
