# Engineering Principles

- Optimize for the approved outcome and simplest sustainable design.
- Prefer cohesive ownership, explicit boundaries, stable contracts, and root-cause fixes.
- Apply DRY to genuinely shared behavior, KISS to avoid cleverness, and YAGNI to avoid speculative systems.
- Avoid both throwaway production shortcuts and premature abstraction.
- Keep changes scoped; do not refactor unrelated legacy code.
- State sources of truth, trust boundaries, failure behavior, and evidence required before implementation.
- Use repository patterns unless they conflict with safety or the approved design.

These principles guide tradeoffs; they do not mandate a particular pattern or class hierarchy.
